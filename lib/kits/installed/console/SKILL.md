# SKILL · console Style Pack

你在用 **console**。它的目的是让一块 16:9 大屏上的**三层信息同时可读**，
并且让**颜色能当判据用**。

判据只有一条：如果这屏灰度化（或用色觉模拟）之后你分不出「攻击 / 待授权 / 已闭环」，
或者 3 米外读不出结论 —— 那它就不是 console。

---

## 0. 先写 Visual Manifest，再写 JSX

```json
{
  "stylePack": "console",
  "productType": "security-operations-console",
  "firstVisual": "深色画布上三列被 2px 规则线切开：左=攻击链节点，中=流式战情结论 + 呼吸点，右=待人授权队列（琥珀）",
  "skeleton": { "stage": "1680x1050", "topbar": 76, "bottombar": 130, "columns": [500, 600, 366] },
  "motionDirection": "event-driven",
  "density": "very-high",
  "colorSemantics": {
    "negative": "攻击 #F4364C",
    "accent": "AI 在产出 #22D3EE",
    "accent2": "待人授权 #F5A524",
    "positive": "已闭环 #2ECC71",
    "series3": "证据引用 #60A5FA"
  },
  "avoid": ["ambient-glow", "glow", "scanline-decoration", "purple-gradient", "particle-globe", "emoji"]
}
```

**先声明 `colorSemantics` 再写界面。** 这套 pack 的颜色是判据，
如果写到一半才决定「这个青色用来强调标题」，语义纪律就已经破了。

---

## 1. 必须做

1. **一色一义**：红=攻击、青=AI、琥珀=待人授权、绿=已闭环、蓝=证据引用。
   任何一个颜色**不得**为第二种含义服务。琥珀不是通用强调色。
2. **等宽只覆盖读数性文本**：数字 / ID / 命令 / 日志 / 审计行 / 证据引用 / 标签。
   中文长句正文用 `--kits-font-body`（无衬线）—— 全站等宽会让中文段落不可读。
3. **所有数字 tabular + slashed-zero**：`font-variant-numeric: tabular-nums
   lining-nums slashed-zero`（`.kits-data` 已经带上了）。ID / IP / 哈希里
   `0` 与 `O` 必须能区分。
4. **间距服务于列对齐**：所有内外边距取 `--kits-space-unit`（4px）的整数倍。
   三列宽度要能被 4 整除，左边界处处对齐。
5. **线只出现在语法位置**：面板边界与列分隔画线；**行与行之间不画线**，
   那里用行高与明度。问自己「这里是不是一个结构转折」，不是「这里好不好看」。
6. **层级只用两轴**：三级墨色（`ink` / `ink-muted` / `ink-faint`）× 三档字重。
   不要引入第三个手段（线、光、留白、材质）。
7. **16:9 单屏不滚动；滚动只发生在面板内部**。长尾交给面板内滚动区，
   不要让整页滚动。
8. **3 米层字号 ≥20px**：结论 `.kits-display`(34–52px)、读数 `.kits-data`(36px)、
   面板标题 24px、说明 `.kits-lead`(≥20px)。13px 标签属于面板内部，**不得**承载
   唯一关键信息。
9. **动效只由状态变化触发**：流式打字 / 呼吸点 / 粒子汇流 / 碎裂盖章 / 划掉重写。
   每一次动画都要能说出它对应哪个事件。
10. **交互动效 ≤240ms**，位移 ≤4px，无回弹。按压反馈 60ms 内必须发生。
11. **状态必须有非颜色的第二通道**：`+2.4%` / `-1.1%` 的符号、状态文字、
    或形状差异。仅靠颜色区分状态一律违规。
12. **骨架对得上**：顶栏 76px（命令条 44px + 上下 16px，控件 38px 必须能排进去）、
    底栏 130px（日志流 4 × 28px）、三列 500 / 600 / 366。

## 2. 禁止做

| 禁止 | 原因 |
|---|---|
| `ambient-glow` / 环境光层 | 控制台的光只能来自真实状态；CSS 里没有 `.kits-ambient` |
| `glow` / bloom / neon | `--kits-color-glow: transparent`，audit 会与声明交叉核对 |
| 扫描线装饰 | 纹理必须是**点阵格位**（离散），不是周期条纹 |
| 蓝紫渐变 | 颜色必须携带语义，不能携带情绪 |
| 粒子地球 | 「展厅大屏」的标志，与本 pack 气质互斥 |
| **emoji** | 字符集是语言与符号，不是表情 |
| 无意义入场动画 | 没有状态变化支撑的动画 = 耗电的噪音 |
| 回弹缓动（含契约默认 spring） | 读数在落定过程中过冲 = 中间态是错的 |
| 全站等宽 | 中文正文会塌成不可读的字块 |
| 处处画线（instrument 式的分格） | 线一旦出现在非语法位置就退化成表格装饰 |
| 一色两义 | 用 AI 青强调与 AI 无关的东西 = 两种含义都失效 |
| `box-shadow` / `backdrop-filter` / `filter` / `text-shadow` | 这三个是 cinematic 落 B 档的原因，本 pack 一个都不用 |
| 半径 > 0 | 控制台的表面是被切出来的，不是被倒出来的 |
| 拿红色画一条普通数据曲线 | 红是**状态**不是序列；第三条曲线用证据蓝 |
| 大留白（面板间 gap > 32px） | 留白在这块屏上是最贵的资源 |
| 正文用 `#5B6E8C`（三级墨） | 它四面都不过 4.5:1，只允许禁用态 / 水印 / 次要图例 |
| card 面上的攻击红正文 | `#F4364C` on `#152238` = 4.16:1，只允许大字或非文本元素 |

## 3. 自检清单

- [ ] 灰度打印后，攻击 / 待授权 / 已闭环是否**仍可区分**？（必须有文字或符号）
- [ ] 是否每个颜色都只有一个含义？有没有哪个颜色被「借去强调」？
- [ ] 中文段落是否是**无衬线**？（全站等宽是违规）
- [ ] 所有数字是否等宽 + tabular？（刷新一次看列有没有跳动）
- [ ] `0` 与 `O`、`1` 与 `l` 在 ID / IP / 哈希里能否区分？
- [ ] 所有间距是否都是 4px 的整数倍？左边界是否处处对齐？
- [ ] 是否存在画在非语法位置的线？（行与行之间不该有线）
- [ ] 是否只用了「明度 × 字重」两轴建立层级？有没有偷偷引入光 / 线 / 材质？
- [ ] 整页是否会在 16:9 下滚动？（不应该；只有面板内部可以滚）
- [ ] 3 米层（`.kits-display` / `.kits-data` / `.kits-lead`）是否全部 ≥20px？
- [ ] 是否出现了任何没有状态变化支撑的动画？
- [ ] 所有交互动效是否 ≤240ms、无过冲、位移 ≤4px？
- [ ] 呼吸点是否**只有一个**，且它标记的确实是「运行中」？
- [ ] `prefers-reduced-motion: reduce` 下呼吸点是否完全关闭？信息是否仍有静态替代？
- [ ] 是否出现了 `box-shadow` / `backdrop-filter` / `filter` / `text-shadow`？
- [ ] 是否出现了 `.kits-ambient` 或任何环境光层？
- [ ] 是否有 emoji？是否有扫描线？是否有蓝紫渐变？
- [ ] 攻击红是否出现在了 card 面的正文尺寸文本上？

## 4. 常见误用

**误用：把 console 当成「更深的 instrument」用，于是处处画 1px 分格线。**
→ 后果：线一旦出现在行与行之间，屏幕就退化成一张电子表格；同时 `syntax-rule`
的立场（线编码结构）被掏空，读者再也分不清哪条线是结构、哪条是装饰。
→ 正确做法：只画面板边界与列分隔。行与行的区分交给 `--kits-row-height`(28px)
与三级明度。

**误用：为了「有科技感」给网格加点流动动画，或者给呼吸点之外的元素也加呼吸。**
→ 后果：控制台上 24 小时运行的动画 = 无意义耗电 + 干扰对真实状态变化的感知。
→ 正确做法：本 pack 只有**一个**循环动效（「运行中」呼吸点）。
其余全部由事件触发，事件结束动画就结束。

**误用：给结论加 `text-shadow` 让它「更醒目」。**
→ 后果：`--kits-color-glow` 是 `transparent`，材质声明是 `glow: forbidden` ——
这不只是审美问题，是**声明与实现不一致**，audit 会判错。
→ 正确做法：醒目靠**字重 + 字号 + 明度**（`luminance-and-weight` 这条维度的全部含义）。

**误用：为了中英混排整齐，把正文也改成等宽。**
→ 后果：中文段落塌成不可读的字块 —— 等宽汉字与等宽拉丁字母在同一行产生参差字距，
而中文没有西文的词间空隙来补这个节奏。
→ 正确做法：等宽只覆盖读数性文本；正文用 `--kits-font-body`。

**误用：拿攻击红画一条非攻击相关的数据曲线，因为「红色比较显眼」。**
→ 后果：红在这块屏上意味着攻击 —— 一条红色的普通曲线会让操作员以为发生了攻击。
这是**误报**，比不显示更糟。
→ 正确做法：第三条曲线用证据引用蓝（`--kits-data-series-3`）。

**误用：把 alert / warning 的全部语义都塞进琥珀，于是琥珀成了通用强调色。**
→ 后果：琥珀的含义比 warning 窄得多 —— 它是「球在你那边」（待人授权）。
用满之后，操作员在待授权队列上反而不再敏感。
→ 正确做法：琥珀**只**出现在待授权对象上。

**误用：为了放下更多内容，让整页滚动。**
→ 后果：「16:9 单屏不滚动」是本 pack 密度成立的前提；一旦整页滚动，
`very-high` 密度就只是「挤」，而操作员也失去了「一屏三层」的态势感知。
→ 正确做法：单屏只放当前战情，长尾进面板内部滚动区。

**误用：把 console 用在移动端主场景。**
→ 后果：三列 500/600/366 在 390px 下降级为单列长页；13px 等宽标签与命令条
导航在触屏上无法精确命中。
→ 正确做法：`mobileCompatible: true` 只表示「不会天然失效」，**不表示推荐** ——
换 pack，或把移动端收窄到 3–5 个核心指标。

## 5. 与其它 pack 的边界

| 你想要 | 换哪一套 |
|---|---|
| 阅读优先（长文、报告） | `editorial` |
| 沉浸与氛围（发布会、叙事） | `cinematic` |
| 一屏塞满必须逐位比对的数字、且不滚动 | `instrument` |
| **16:9 大屏 + 三层信息 + 颜色当判据 + 面板内滚动** | `console`（本套） |

**console 与 instrument 最容易混**，三处关键差异：

| | instrument | console |
|---|---|---|
| 等宽覆盖范围 | **全站**（含正文） | **只覆盖读数性文本** |
| 线的立场 | 处处实线分格 | 线只出现在语法位置 |
| 密度与滚动 | `high`：一屏放下全部内容 | `very-high`：单屏只放当前战情，面板内滚动是设计的一部分 |

同一页混用（例如「主控台用 console，日报叙事用 editorial」）→
两个 `data-kits-pack` 容器分区。

---

## 6. 换 pack 时你唯一要改的东西

```diff
- <section data-kits-pack="console">
+ <section data-kits-pack="editorial">
```

`.kits-control--authorize` / `.kits-control--danger` / `.kits-lead` 是 console 专属
语义的产物，换 pack 后它们会失去样式 —— **这是预期行为**。
一个「待人授权琥珀按钮」不该出现在编辑式页面上。如果你发现「必须保留它们」，
说明选错 pack 了。
